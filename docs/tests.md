# Тесты

На главной странице доступны «Создать тест», «Мои тесты» и «Пройти тест».
Автором может быть преподаватель или администратор с активной ролью в вузе.
У теста одно обязательное `time_to_complete`, в секундах на всё прохождение.
У вопросов нет отдельного времени. Типы и варианты такие же, как в квизах:
`single` — один правильный вариант, `multy` — несколько. Вопросы и варианты
могут содержать картинки из существующего сервиса загрузки.

Черновик допускает незавершённое содержимое. Публикация требует названия,
хотя бы одного вопроса, текста вопросов, минимум двух заполненных вариантов
и правильных ответов. После публикации содержимое и статус неизменны.
Сохранение проверяет `revision`, обновление вопросов выполняется в одной транзакции.
`updated_at` у тестов нет; списки упорядочены по `created_at`, от новых к старым.

`public` виден в списке активным студентам своего вуза. `private` доступен
тем же студентам по ссылке `/?test=<UUID>` или идентификатору. Ссылка не даёт
доступа пользователям других вузов. После входа по ссылке студенту предлагается
начать тест: таймер не запускается автоматически при авторизации.
Сессии ведущего и общие коды для тестов не создаются.

Пока разрешена одна попытка на пару студент/тест. Повторное начало возвращает
существующую попытку, включая завершённую. В `test.test_in_process` сохраняются
текущий вопрос, начало, срок окончания и статус `in_progress/completed/expired`.
Выход и перезагрузка не продлевают время. Незавершённая попытка, в том числе
private, видна в списке доступных тестов. Откройте её, чтобы продолжить.

Ответ окончательный: вернуться к предыдущему вопросу и заменить ответ нельзя.
Запись ответа, его вариантов и переход к следующему вопросу атомарны. Повтор
идентичного запроса безопасен, включая повтор после завершения. Конкурентные
запросы блокируют строку попытки; другой ответ на уже принятый вопрос отклоняется.
Время проверяется сервером после блокировки и непосредственно перед сохранением.
Просроченная попытка помечается завершённой при обращении студента или автора;
таймер интерфейса запрашивает окончательное состояние по истечении времени.

Во время прохождения студент получает только текущий вопрос без `is_correct`,
служебных ключей хранилища и будущих вопросов. После завершения доступны его
баллы и количество ответов. За точное совпадение набора выбранных вариантов
с правильными — 1 балл, иначе 0. Автор видит имена, статус, прогресс и баллы
своих учеников через «Результаты учеников». Кнопка «Обновить» обновляет отчёт.
Активная роль проверяется при каждом обращении.

| Метод | Путь | Назначение |
| --- | --- | --- |
| POST | `/v1/tests` | Создать черновик или опубликованный тест |
| PUT | `/v1/tests/{test_id}` | Заменить черновик, обязательна revision |
| GET | `/v1/tests` | Последние 100 тестов автора |
| GET | `/v1/tests/{test_id}` | Полное содержимое для автора |
| GET | `/v1/tests/available` | Публичные тесты вуза и личные попытки студента, до 100 |
| POST | `/v1/tests/{test_id}/start` | Начать или продолжить, тело `{}` |
| GET | `/v1/tests/{test_id}/progress` | Восстановить сохранённый прогресс |
| POST | `/v1/tests/{test_id}/answers` | Сохранить `question_id` и массив `answer_ids`, вернуть следующий вопрос/результат |
| GET | `/v1/tests/{test_id}/results` | Отчёт автора о прохождениях |

Все запросы требуют Bearer JWT. Создание возвращает 201 с `test_id`, `status`,
`revision`; обновление — 200. Ошибки полей — 400, доступ — 403/404,
конфликты версии/публикации/прогресса — 409. Ответы не кешируются.

Новая база получает схему автоматически из `postgresql/schemas/db_1.sql`.
Для существующей базы примените повторяемую миграцию без удаления данных:

```powershell
Get-Content postgresql/migrations/007_tests.sql -Raw | docker compose exec -T postgres psql -U rumpelquiz -d rumpelquiz -v ON_ERROR_STOP=1
```

После изменения исходников пересоберите и перезапустите backend.
Проверки: `node --test frontend/tests/*.test.js` и в dev container
`cmake --build build-debug -j4 && ctest --test-dir build-debug --output-on-failure`.
