# Поиск программ и групп

Публичные GET-эндпоинты без авторизации:

- `/v1/education/search/programs?university_id=<uuid>&name=<text>`
- `/v1/education/search/groups?university_id=<uuid>&name=<text>`

Оба параметра обязательны. Некорректный или отсутствующий UUID возвращает
HTTP 400 с `{"success": false, "error": "invalid_university_id"}`.
Пустой или отсутствующий `name` возвращает HTTP 400 с
`{"success": false, "error": "invalid_name"}`.
Краевые пробелы, табуляция и переводы строк удаляются.

Поиск выполняется по подстроке без учёта регистра внутри выбранного вуза.
Символы `%`, `_` и `!` воспринимаются буквально. Параметры передаются отдельно
от SQL. Результаты сортируются по названию и ID, названия факультетов — по
названию и ID факультета.

Успешный ответ: HTTP 200, `success: true` и массив `programs` или `groups`.
Программа содержит `id`, `name`, `facultet_names` (массив строк).
Группа содержит те же поля и `program_name`. У группы без программы
`program_name: null`, `facultet_names: []`.
Одноимённые сущности возвращаются отдельно, каждая со своим ID.
Если совпадений нет или вуз не существует, массив пустой.

При более чем 30 совпадениях ответ HTTP 200:

```json
{
  "success": false,
  "error": "too_many_results",
  "message": "Введите более точное название",
  "programs": []
}
```

Для поиска групп вместо `programs` возвращается `groups: []`.
Частичная выдача не возвращается. Ограничение применяется к найденным
сущностям до присоединения факультетов: несколько факультетов у одной
программы не влияют на лимит. Каждый поиск выполняется одним запросом
к БД с `LIMIT 31`; точное число всех совпадений не подсчитывается.
