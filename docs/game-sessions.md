# Игровые сессии

В «Мои квизы» нажмите на опубликованный квиз. Во всплывающем окне выберите
«Создать сессию» или «Посмотреть старые сессии». Создание открывает прежний
экран квиза: введите название и нажмите «Создать сессию».
Черновики открываются в редакторе.
История содержит завершённые и отменённые сессии, от новых к старым:
название, преподаватель, дата создания и число участников.
Нажатие на сессию открывает её результаты; можно вернуться к списку.
Экран ведущего показывает код, QR, список участников, текущий вопрос и таймер.
«Следующий вопрос» начинает игру или закрывает предыдущий вопрос и открывает
следующий. Последний вопрос остаётся открытым до срока или закрытия сессии.
«Закрыть сессию» завершает игру; закрытие лобби помечает её отменённой.

Студент входит через «Присоединиться по коду» или ссылку из QR. Нужна активная
роль student в вузе сессии. Вход сохраняется навсегда в рамках истории сессии:
отключение и повторный вход не удаляют и не дублируют участника.
Ответ отправляется один раз, с одним или несколькими вариантами.
Повтор идентичного запроса возвращает успех, не меняя время ответа.
Другой набор вариантов после сохранения отклоняется.

При перезагрузке вкладки восстанавливаются авторизация и ID игры.
Содержимое, текущий вопрос, время и принятый ответ заново запрашиваются с сервера.
ID создания сохраняется до успешной загрузки комнаты, поэтому потеря ответа
сервера не создаёт повторную комнату. Запрос next содержит ожидаемый question_id:
повтор не перелистывает игру ещё раз.

Открытый экран игры получает события через GET /v1/game/sessions/{id}/events.
Первое событие содержит персональное состояние; новый вопрос передаётся целиком
вместе со ссылками на изображения. Ведущий получает уведомление о входе и ответе
и обновляет своё состояние одним GET. При обрыве поток переподключается и снова
получает полное состояние. Обычные действия по-прежнему идут через POST.
Таймер обновляется локально каждую секунду; периодических запросов состояния нет.
Студент отдельно подтверждает присутствие каждые 10 секунд небольшим POST-запросом
`/v1/game/sessions/{id}/presence`. При уходе со страницы или закрытии вкладки
браузер отправляет последний запрос с `keepalive`. Преподаватель получает через
SSE событие `presence`: список `{user_id, online}`, и видит уведомления с именем,
временем обнаружения и отметками «Нет связи» / «В квизе».
Явный выход учитывается через 8–10 секунд, отсутствие подтверждений — через
35–37 секунд от последнего успешного подтверждения. Если последний запрос при
закрытии не дошёл, используется этот же тайм-аут. Быстрая перезагрузка страницы
не вызывает уведомления. Открытые вкладки одного участника объединяются;
выходом считается отсутствие всех вкладок. Переключение вкладок само по себе
не отслеживается. При приостановке браузера возможна потеря подтверждений связи.
Причины «вышел» и «пропал интернет» технически не различаются.
Присутствие доступно только ведущему; учащиеся не получают чужие статусы.
Список последних 20 уведомлений хранится на открытом экране ведущего и очищается
при перезагрузке; текущее состояние восстанавливается с сервера. Статусы живут
в памяти одного процесса и очищаются после закрытия сессии или перезапуска сервера.
Поток использует текущий Bearer JWT и закрывается не позже срока его действия.
После сетевой ошибки доступна кнопка обновления состояния.
Рассылка событий пока работает внутри одного процесса сервиса. Для нескольких
экземпляров понадобится общий канал уведомлений между ними.
Срок приёма ответа проверяет сервер под блокировкой сессии.

После завершения последним событием SSE отправляется `results`: полное состояние
сессии с общей таблицей участников. Затем сервер закрывает поток, а клиент
прекращает переподключения. Подключение к уже завершённой или отменённой сессии
также возвращает `results` и закрывается. Дополнительный GET для этого события не нужен.

Ведущий и все участники видят одинаковые результаты: имя, число отправленных
и полностью правильных ответов, баллы. Полностью правильный ответ даёт 1 балл;
при нескольких вариантах выбранный набор должен точно совпасть с правильным.
Ошибка, лишний вариант или пропуск дают 0; скорость не влияет. Сортировка — по
баллам убывающе, при равенстве — по времени подключения и ID участника.
Поле `rank` рассчитывается на сервере по баллам: при ничьей участники делят
место, а следующие номера пропускаются (например, 1, 2, 2, 4). Время подключения
влияет только на порядок строк с одинаковыми баллами. В отменённой сессии
`rank` равен null. Итоги игры, SSE и история используют один расчёт.
Экран результатов показывает призовые места с ненулевыми баллами, общую таблицу
с местами и прогрессом правильных ответов; собственная строка выделена меткой «Вы».
Участники без ответов тоже включены. В отменённой до начала сессии у всех 0 баллов.
История и SSE используют один подсчёт по сохранённым ответам.
Правильные варианты не передаются через API игрового состояния.

## Локальная сеть и QR

QR строится в браузере встроенной библиотекой qrcode-generator 1.4.4.
Внешних запросов для генерации нет; npm-сборка не нужна.
Ссылка имеет вид `http://адрес-сервера:8080/?join=012345`.
Если сайт открыт через localhost, в «Адрес для участников» ведущий может указать
адрес компьютера в локальной сети. Серверный порт должен быть доступен устройствам.
Код из ссылки сохраняется на время входа или регистрации.

## База и API

Новые базы, включая testsuite, получают game из postgresql/schemas/db_1.sql.
Для существующей базы выполните postgresql/game_schema.sql без удаления данных.
Для обновления уже созданной игровой схемы достаточно миграции
`postgresql/migrations/006_game_session_names.sql`. Применяйте её до запуска нового бэкенда.
Старые сессии получают название «Сессия <UUID>».
Тест контролирует совпадение отдельного скрипта и встроенного блока схемы.

Все маршруты требуют JWT:

- POST /v1/game/sessions — создать свою сессию опубликованного квиза.
- POST /v1/game/sessions/{id}/next — следующий вопрос.
- POST /v1/game/sessions/{id}/close — закрытие.
- GET /v1/game/sessions/{id} — состояние ведущего или зарегистрированного участника.
- GET /v1/game/sessions/{id}/events — поток событий ведущего или участника.
- GET /v1/quizzes/{id}/sessions — история завершённых и отменённых сессий;
  доступна активным преподавателям и администраторам вуза квиза.
- GET /v1/game/sessions/{id}/results — результаты завершённой или отменённой
  сессии; доступны активным преподавателям/администраторам вуза и студентам,
  зарегистрированным в этой сессии. До завершения — 409 `session_not_finished`;
  отсутствующая или недоступная сессия — 404 `session_not_found`.
- POST /v1/game/sessions/join — вход с полем code.
- POST /v1/game/sessions/{id}/answers — question_id и массив answer_ids.
- POST /v1/game/sessions/{id}/presence — подтверждение присутствия участника:
  `client_id` (новый UUID для каждого открытия экрана), `sequence` (возрастающее
  целое число), `online` (boolean). Пользователь определяется по JWT; чужой
  user_id передать нельзя. Запоздавшие запросы с меньшим sequence игнорируются.

Времена JSON передаются в миллисекундах Unix, в полях с суффиксом _ms.
Состояние сохраняется в PostgreSQL; изображения подписываются заново при чтении.

Создание принимает обязательные поля `quiz_id`, `session_id`, `name`.
Название обрезается по краям и должно содержать от 1 до 200 Unicode-символов;
пустое, отсутствующее или нестроковое название возвращает 400 invalid_request.
Названия не уникальны. Повтор session_id с другим названием возвращает 409 request_id_conflict.
Поле session.name содержит название сессии; GET также возвращает session.quiz_name.
