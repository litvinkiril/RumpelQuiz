# Создание квизов

После входа на главном экране доступны «Создать квиз» и «Мои квизы».
Нужна активная роль teacher или admin в выбранном вузе.

Черновик сохраняет незавершённые вопросы и ответы. Публикация (`status=ready`)
дополнительно проверяет название, наличие вопросов, их текст, минимум два
заполненных ответа и правильные варианты: один для single, хотя бы один для
multy. Ответ может содержать текст, картинку или оба. Время вопроса null
означает наследование общего времени. Позиции определяются порядком массивов.
Общие ограничения размеров, времени и доступа действуют и для черновиков.

API:
- POST /v1/quizzes — создание, ответ 201 с quiz_id, status, revision.
- PUT /v1/quizzes/{id} — полная замена содержимого, требуется revision.
- GET /v1/quizzes/{id} — загрузка своего квиза с временными ссылками картинок.
- GET /v1/quizzes — последние 100 своих доступных квизов.
- POST /v1/media/images — загрузка картинки, multipart file.

Запись квиза и пакетная запись вопросов/ответов выполняются в одной транзакции.
Устаревшая revision возвращает 409; чужой квиз недоступен. Опубликованный квиз
доступен только для просмотра: любые обновления, включая возврат в черновик,
отклоняются с 409 `quiz_published`. Проверка выполняется под блокировкой строки
в транзакции, поэтому одновременные запросы не обходят запрет.
Вопросы и ответы при сохранении черновика и публикации получают новые внутренние
идентификаторы; после публикации они неизменны. Существующие квизы со статусом
`ready` также считаются опубликованными. Прохождение и сессии пока не реализованы;
они смогут ссылаться на опубликованный квиз без отдельной копии содержимого.

## Запуск

Для существующей базы один раз выполните
`postgresql/migrations/005_quizzes_media.sql`. Новая база получает эти таблицы
из `postgresql/schemas/db_1.sql`. Миграция не удаляет существующие данные.

Пересоберите dev container для установки libstb-dev и libwebp-dev, либо
установите эти пакеты в текущем контейнере. Затем выполните `make start-debug`.
Приложение слушает порт 8080. Ключи S3 и JWT загружаются из локального `.env`.
Загрузка картинок требует включённого S3; текстовые квизы работают без него.

## Проверки

В контейнере от обычного пользователя:

```sh
cmake --preset debug
cmake --build build-debug -j4
ctest --test-dir build-debug --output-on-failure
```

Фронтенд: `node --test frontend/tests/*.test.js`.
API-тесты используют отдельную тестовую базу, не пользовательские данные.
