# Создание квизов

После входа на главном экране доступны «Создать квиз» и «Мои квизы».
Нужна активная роль teacher или admin в выбранном вузе.

Черновик сохраняет незавершённые вопросы и ответы. Публикация (`status=ready`)
дополнительно проверяет название, наличие вопросов, их текст, минимум два
заполненных ответа и правильные варианты: один для single, хотя бы один для
multy. Ответ может содержать текст, картинку или оба. Время вопроса null
означает наследование общего времени. Позиции определяются порядком массивов.
Общие ограничения размеров, времени и доступа действуют и для черновиков.

API:

- POST /v1/quizzes — создание, ответ 201 с quiz_id, status, revision.
- PUT /v1/quizzes/{id} — полная замена содержимого, требуется revision.
- GET /v1/quizzes/{id} — загрузка своего квиза с временными ссылками картинок.
- GET /v1/quizzes — последние 100 своих доступных квизов.
- GET /v1/quizzes/search — поиск квизов в каталоге вузов преподавателя/администратора.
- POST /v1/quizzes/{quiz_id}/favourite — добавить квиз в избранное.
- DELETE /v1/quizzes/{quiz_id}/favourite — удалить квиз из избранного.
- POST /v1/media/images — загрузка картинки, multipart file.

Запись квиза и пакетная запись вопросов/ответов выполняются в одной транзакции.
Устаревшая revision возвращает 409; чужой квиз недоступен. Опубликованный квиз
доступен только для просмотра: любые обновления, включая возврат в черновик,
отклоняются с 409 `quiz_published`. Проверка выполняется под блокировкой строки
в транзакции, поэтому одновременные запросы не обходят запрет.
Вопросы и ответы при сохранении черновика и публикации получают новые внутренние
идентификаторы; после публикации они неизменны. Существующие квизы со статусом
`ready` также считаются опубликованными. Игровые сессии и прохождение описаны
в `docs/game-sessions.md`.

## Каталог и избранное

После входа главное меню открывает разделы «Квизы», «Тесты» и профиль.
Студентам доступны прохождение квиза и назначенные тесты. Преподавателям
и администраторам доступны создание заданий и «Квизы → Посмотреть квизы»:
поиск по названию, фильтр избранного и загрузка следующих результатов.
Кнопка «Мои квизы» в каталоге открывает свои квизы для запуска сессий
и просмотра истории. «Посмотреть тесты» и «Домашки» пока неактивны.

Все три маршрута каталога требуют Bearer JWT. Поиск требует `name`
(подстрока названия без учёта регистра, пустая строка — все названия),
`favourites` (строго `true` или `false`) и `count_spend` (число пропущенных
результатов от 0 до 2147483647). Неверные или отсутствующие параметры
возвращают 400 с `{"success":false,"error":"invalid_search_params"}`.

Ответ поиска — `{"quizzes":[...]}`. Поля квиза: `quiz_id`,
`creator_first_name`, `creator_last_name`, `title`, `question_count`,
`is_favourite`. Отсутствующие имена автора представлены пустыми строками.
В каталоге видны draft/ready квизы всех авторов из вузов, где пользователь —
активный teacher/admin. Без подходящих ролей возвращается пустой список.
Фильтры применяются до пагинации; страница содержит до 10 квизов.
Порядок — `created_at DESC, id`, независимо от времени редактирования.
Символы `%` и `_` ищутся буквально.

Для POST/DELETE передаётся только `quiz_id` в пути, тело не нужно.
Пользователь определяется по JWT. Успех — 200 с `{"success":true}`;
повторные запросы безопасны. Неверный UUID возвращает 400 с `invalid_quiz_id`.
POST для отсутствующего или недоступного квиза возвращает 404 с
`quiz_not_found`. DELETE удаляет только личную запись, в том числе после
отзыва роли. Избранное квизов хранится отдельно в `quiz.favourites`
и не влияет на избранное тестов.

## Запуск

Для существующей базы один раз выполните
`postgresql/migrations/005_quizzes_media.sql`. Новая база получает эти таблицы
из `postgresql/schemas/db_1.sql`. Миграция не удаляет существующие данные.

Для существующей базы таблица избранного добавляется повторяемой миграцией
`postgresql/migrations/009_quiz_favourites.sql`:

```powershell
Get-Content postgresql/migrations/009_quiz_favourites.sql -Raw | docker compose exec -T postgres psql -U rumpelquiz -d rumpelquiz -v ON_ERROR_STOP=1
```

Миграция совместима с таблицей, созданной в pgAdmin, с колонками `user_id`,
`quiz_id`, `created_at` и первичным ключом `(user_id,quiz_id)`.
Существующие записи сохраняются. Новая база создаёт таблицу автоматически.

Пересоберите dev container для установки libstb-dev и libwebp-dev, либо
установите эти пакеты в текущем контейнере. Затем выполните `make start-debug`.
Приложение слушает порт 8080. Ключи S3 и JWT загружаются из локального `.env`.
Загрузка картинок требует включённого S3; текстовые квизы работают без него.

## Проверки

В контейнере от обычного пользователя:

```sh
cmake --preset debug
cmake --build build-debug -j4
ctest --test-dir build-debug --output-on-failure
```

Фронтенд: `node --test frontend/tests/*.test.js`.
API-тесты используют отдельную тестовую базу, не пользовательские данные.
Каталог квизов проверяется в `tests/test_search_quizzes.py`, а операции
избранного — в `tests/test_catalog_quiz_favourites.py`.
