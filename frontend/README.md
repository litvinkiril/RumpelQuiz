# Фронтенд RumpelQuiz

Интерфейс использует обычные ES-модули и CSS. Отдельной сборки JavaScript нет:
CMake встраивает публичные файлы в сервер, браузер загружает модули с того же адреса.

## Где менять код

```text
frontend/
  app.js                 запуск приложения
  index.html             общая оболочка и верхнее меню
  styles.css             порядок подключения стилей
  assets/
    core/
      api.js             HTTP-запросы и ошибки
      controller.js      соединение разделов и навигация
      messages.js        сообщения об ошибках сервера
      session.js         вход и обновление токенов
      state.js           начальное состояние и сохранение сессии
    features/
      auth/              вход, регистрация, восстановление пароля
      home/              главный экран и выбор раздела
      profile/           профиль и описание пользователя
      education/         учебные заведения, администраторы, поиск людей
      user-creation/     создание пользователей и выбор факультета
      catalog/           общий каталог квизов и тестов, поиск и избранное
      quizzes/           создание квизов и история сессий
      tests/             создание и прохождение тестов
      game/              игровая сессия, события сервера, результаты
    shared/              экранирование HTML, иконки, роли и карточки людей
    ui/
      view.js            выбор страницы по состоянию
      mount.js           обновление интерфейса, фокус, диалоги, таймеры
      events.js          обработка форм, кнопок и ввода
    styles/              стили по разделам
  tests/                 проверки поведения интерфейса
```

В разделе `controller.js` выполняет действия и обновляет состояние, `model.js`
содержит модели, проверки и подготовку данных, `view.js` возвращает разметку.
У простых разделов есть только нужные им файлы. Файлы `quiz.js`, `test.js` и
`game.js` в корне сохраняют прежние экспорты для тестов и существующих ссылок.

Например, внешний вид профиля меняется в `assets/features/profile/view.js`,
его загрузка — в `assets/features/profile/controller.js`, стили — в
`assets/styles/account.css`.

Шаблоны размечены тегом `html`, чтобы форматировщик понимал HTML внутри JavaScript.
Он собирает строку без преобразований. Пользовательский текст нужно экранировать
через `escapeHtml` перед вставкой в шаблон.

## Проверки и форматирование

Для тестов нужен только Node.js:

```sh
node --test frontend/tests/*.test.js
```

Для форматирования из папки `frontend`:

```sh
pnpm install --frozen-lockfile
pnpm format
pnpm format:check
```

Prettier используется только при разработке. Он не нужен серверу и не участвует
в загрузке приложения. Сторонняя библиотека QR-кодов находится в `vendor` и
не переформатируется.

## Добавление страницы

1. Добавьте нужные файлы в `assets/features/<раздел>`.
2. Подключите контроллер в `assets/core/controller.js`, представление — в
   `assets/ui/view.js`, действия — в `assets/ui/events.js`.
3. Добавьте стили в `assets/styles` и подключите их в `styles.css`.
4. Проверьте поведение и пересоберите сервер.

`cmake/EmbedFrontend.cmake` автоматически подхватывает новые JS/CSS-файлы внутри
`assets`. Для каждого модуля не нужно добавлять отдельный серверный маршрут.
Сервер выдаёт только встроенные публичные ресурсы; тесты, зависимости и конфигурация
в таблицу ресурсов не входят. Порядок импортов в `styles.css` влияет на каскад CSS.
